# Cocoon App — план доведения MVP до продукта

Цель: лёгкое, красивое кросс-платформенное приложение-клиент сети COCOON
(децентрализованный AI-инференс на TON): чат с ИИ, кошелёк и платежи,
статус сети. Windows + macOS сейчас, Android/iOS позже.

## Архитектура

```
┌─────────────────────────────────────────────┐
│  Tauri 2 (Rust shell, ~5–10 МБ)             │
│  ├─ Frontend: React + TypeScript + Tailwind │
│  │  (чат, онбординг, кошелёк, сеть)         │
│  └─ Sidecar-менеджмент: spawn/health/stop   │
└───────────────┬─────────────────────────────┘
                │ localhost HTTP (один порт)
┌───────────────▼─────────────────────────────┐
│  gocoon-runner (чистый Go, статический бинарь) │
│  ├─ OpenAI-совместимый /v1/* (+SSE-стриминг)│
│  ├─ App API: кошелёк, состояние, история    │
│  ├─ pkg/cocoon: сессии, инференс, платежи   │
│  └─ pkg/contracts: TON-кошелёк и контракты  │
└───────────────┬─────────────────────────────┘
                │ TCP + PoW + TLS1.3 (RA-TLS)
        COCOON proxy (TEE) → worker (TEE, GPU)
```

Ключевые решения:

- **Ядро — gocoon, не C++ клиент.** Портировать `cocoon-api` (C++) под
  Windows не нужно: gocoon кросс-компилируется в статические бинари
  (linux/darwin/windows × amd64/arm64, android/arm64) без CGO.
  `cocoon-api` остаётся эталоном протокола.
- **Оболочка — Tauri 2** вместо самодельной webview_go + Win32-хаков:
  нормальное окно/titlebar/трей, инсталляторы, автообновление, и путь на
  iOS/Android в той же кодовой базе.
- **Один sidecar.** Всё, что сейчас делает `cmd/gocoon/ui.go` (75 КБ
  монолит: кошелёк, конфиг, спавн раннера, чат-прокси), переезжает в
  общий пакет и отдаётся через HTTP API раннера. Браузерный `gocoon ui`
  остаётся на тех же хендлерах.

## Фазы

### 0. Снапшот (← сначала)
Закоммитить текущий незакоммиченный MVP в ветку `app-rework`, чтобы
ничего не потерять.

### 1. Ядро (логика)
- Рефакторинг `ui.go` → `pkg/appserver`: state, wallet init/**import**,
  backup, funding QR, models, chat, logs. Влить в control plane раннера.
- **Вернуть стриминг**: в 0.2.0 `stream:true` принудительно выключен,
  хотя протокол поддерживает частичные ответы (`client.queryAnswerPart*`,
  `Session.RunQuery` уже отдаёт канал `Chunk`). Восстановить SSE на
  `/v1/chat/completions`, разобраться с причиной отключения, покрыть
  тестами через `pkg/cocoon/internal/fakeproxy`.
- Персистентность: история диалогов и сессии в bbolt (data dir).

### 2. Приложение (Tauri 2) — ✅ каркас готов
- Воркспейс `cocoon-app/`: `gocoon/` (форк, ядро) + `desktop/` (Tauri-апка).
- Скаффолд `desktop/`: Tauri 2 + React + TS + Vite (Tailwind — при редизайне).
- gocoon-runner как Tauri sidecar (externalBin), lifecycle из Rust.
- Demo-режим на fakeproxy — разработка UI без траты TON (сеть mainnet-only,
  полный цикл стоит ~20 TON).

### 3. UI/UX (экраны v1)
1. **Онбординг**: создать/импортировать кошелёк → показ recovery phrase с
   подтверждением → funding QR + живой баланс → деплой контракта с
   прогрессом → готово.
2. **Чат**: стриминг, markdown + подсветка кода, выбор модели, цена
   сообщения в TON, история диалогов, остановка генерации.
3. **Кошелёк**: баланс owner/node, статус платёжного канала,
   topup / close / withdraw с понятными состояниями и подтверждениями.
4. **Сеть**: подключение к прокси, статус аттестации, модели и цены,
   воркеры, логи/диагностика.
5. **Настройки**: data dir, порт, бэкап, версия ядра.

Дизайн: тёмная тема по умолчанию, брендинг Cocoon (egg-ассеты в
`cmd/gocoon/assets`), TON-акценты, аккуратная типографика.

### 4. Сборка и дистрибуция
- `tauri build`: Windows NSIS/MSI; macOS .app/.dmg (подпись и нотаризация —
  нужен Apple Developer аккаунт; сборка на Mac или GitHub Actions).
- CI matrix: go test → кросс-сборка раннера → tauri-action.
- Tauri updater — v1.1.

### 5. Мобильный трек (позже, не блокирует ПК)
Tauri 2 умеет iOS/Android, но sidecar-процессы на мобилках ограничены
(iOS вообще запрещает спавн процессов). Путь: собрать ядро библиотекой
(gomobile / c-archive) и звать через FFI из Rust. Отдельное исследование.

## Риски / открытые вопросы
- Причина отключения стриминга в 0.2.0 (вероятно, фрейминг чанков) —
  выяснить до восстановления.
- Mainnet-only: полноценное e2e-тестирование стоит реальных TON;
  для разработки — fakeproxy/demo-режим.
- macOS-сборку нужно где-то выполнять (нет Mac под рукой → GitHub Actions).
- Upstream: ядро живёт в форке attikusfinch/gocoon (ветка app-rework),
  upstream — TONresistor/gocoon; полезные фиксы ядра можно предлагать
  апстриму.
